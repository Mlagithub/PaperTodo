# 意图陈述：PaperTodo MinIO 同步插件 (MinIO Sync Plugin)

- **创建时间**: 2026-03-30
- **当前状态**: 已确认 (Confirmed)

## 1. 核心意图梳理

- **Outcome (目标交付)**：一个基于 MinIO (S3 兼容) 的跨设备双向同步插件，支持多电脑串行接力，包含便签、待办项、Note 文本与图片附件。
- **User (服务对象)**：在多台电脑（如办公室与家里）流转使用 PaperTodo、且拥有自建 MinIO/对象存储的用户。
- **Why now (核心诉求)**：换机时无法自动续接工作桌面的便签与待办，手动复制文件繁琐且容易导致数据丢失或版本不同步。
- **Success (验收标准)**：在一台电脑写完便签/待办/插入图片并同步后，另一台电脑打开能自动拉取并呈现相同内容；日常后台自动静默同步，UI 提供直观的状态灯（同步中/已同步/失败）与手动同步按钮。
- **Constraint (核心约束)**：
  1. **内容优先**：仅同步业务内容（便签元数据、待办项状态与文本、Note 正文）与图片二进制资产，不强制对齐跨设备的绝对窗口物理坐标（避免异构屏幕、多屏及不同 DPI 下错位）；
  2. **安全兜底**：网络脱节或并发修改导致冲突时，绝不静默覆盖本地数据，采用保留双方的策略（自动生成 `[冲突副本]` 或提示确认）；
  3. **插件边界**：作为独立插件运行，遵循 PaperTodo 插件与持久化安全规范，不破坏本地 `data.json` 与 LMDB 资产存储的完整性。
- **Out of scope (明确不做)**：
  1. 不做多端同时在线并发实时协同（CRDT/OT）；
  2. 不引入中心化账号体系或非 S3/MinIO 的第三方专属网盘支持；
  3. 不将桌面窗口坐标强行作为全局强制一致项同步。

## 2. 关键设计考量与前提

1. **同步触发时机**：
   - 自动触发：应用启动就绪后自动拉取远端增量/检查最新版本；便签修改防抖后后台静默推送；应用退出前执行一次同步同步。
   - 手动触发：在顶栏或托盘菜单提供「立即同步」按钮。
2. **状态可视化**：
   - 提供轻量状态指示器（如：空闲/已同步、同步中、同步错误/需要关注）。
3. **冲突处理**：
   - 串行接力为主要工作模式；若发生分叉冲突，将冲突便签另存为 `[冲突副本]` 供用户人工核对，不强制以覆盖解决。
